# Kakao Mining — 카톡 단톡방 → 창작 연료 채굴

대용량 카카오톡 대화 export에서 소설 재료를 캔다. **통독하지 않는다. 받아쓰지 않는다.** 샘플링으로 결을 파악하고, 관찰을 해석으로, 실화를 가명화된 허구 재료로 바꾼다. 산출물은 character-designer·plot-architect·prose-writer가 바로 받는 자료다.

## 작업 순서
1. **규모·기간·멤버 파악** (집계만, 정독 금지)
2. **샘플 정독** (head/중간/후반 + 화제별 대표 구간)
3. **네 가지 추출** (원형 / 씨앗 / 관계 / 말투)
4. **가명화·각색 처리**
5. **`_workspace/00_source_*.md` 출력**

---

## 1. 카톡 export 포맷 파싱

표준 카카오톡 내보내기 포맷:
- 헤더: 첫 줄 `<방이름> 님과 카카오톡 대화` / `저장한 날짜 : YYYY-MM-DD HH:MM:SS`
- 날짜 구분선: `--------------- 2026년 4월 2일 목요일 ---------------`
- 메시지: `[닉네임] [오전/오후 H:MM] 내용`
- 닉네임에 출생연도 접미가 흔함: `우끼끼양_83`, `티라떼 87`, `뿌비스 96`, `찌롱86`, `불네오 94` → 끝 두 자리가 출생연도면 나이대를 추정한다.
- 한 사람이 짧은 메시지를 **연속으로 쏘는** 패턴이 잦다(한 발화를 여러 줄로 쪼갬). 원형의 말투 리듬으로 읽는다.
- `이모티콘`, `사진`, `동영상`, `(이모티콘)` 같은 첨부 표시는 내용이 아니라 행동(리액션) 신호로 읽는다.

## 2. 샘플링 전략 (통독 금지)

14만 줄급은 절대 통째로 Read하지 않는다. Bash로 표본을 뜬다.

```bash
F=docs/KakaoTalk_*_group.txt
wc -l $F                                          # 규모
grep -c '^---------------' $F                     # 날짜 헤더 수 = 대략 기간(일수)
grep -m1 '^---------------' $F; grep '^---------------' $F | tail -1   # 시작/끝 날짜
grep -oE '^\[[^]]+\]' $F | sort | uniq -c | sort -rn | head -25        # 발화 빈도 상위 멤버
head -40 $F                                       # 도입부 결
sed -n '70000,70060p' $F                          # 중간 구간
sed -n '120000,120060p' $F                        # 후반 구간
grep -cE '소장|입주민|회식|술' $F                 # 화제 밀도 측정(정독 전 스캔)
```

원칙:
- **빈도 상위 멤버 = 주연 후보, 하위 = 조연/엑스트라.** 25명을 평면 나열하지 말고 압축한다.
- 화제는 `grep -c`로 밀도만 재고, 밀도 높은 화제의 **대표 구간만** sed로 정독한다.
- 톤을 한 구간으로 단정하지 않는다. 최소 3~4개 날짜 구간을 떠서 웃김·뭉클함·다툼·일상의 결을 두루 본다.

### [원형 코드명: 예 "놀림담당 막내 96"]
- 추정 나이대: (출생연도 접미 근거)

- 관심사/화제:

## 4. 가명화·각색 원칙 (필수, 위반 금지)

- **개인정보는 산출물에 절대 옮기지 않는다.** 실명·전화번호·주소·계좌·특정 직장/실명 식별정보·외부 링크(유튜브 등 개인 공유) → 발견 즉시 추상화하거나 '가명화 필요'로만 표기.
- **닉네임은 코드명으로 추상화한다.** `❤️ 맞짱 전문 뿌비스 96` → `놀림 잘 받는 막내 96` 같은 기능적 코드명. 실닉네임 원문은 추적용 최소 참조로만 남긴다.
- **실인물 1:1 복제 금지.** 인물은 합성·각색한다. 한 캐릭터에 여러 사람의 말버릇을 섞고, 사건은 압축·과장·재배치한다.
- **'관찰'과 '각색 제안'을 구분 표기한다.** 무엇이 실제 결이고 무엇이 창작 가공인지 산출물에서 명확히 나눈다.
- **실인물 보호 > 창작 자유.** 의심되면 더 추상화한다. 단톡방의 따뜻한 결은 살리되, 누군가 자기 대화를 알아보고 상처받지 않게 한다.

## 5. 출력 파일 컨벤션
- 모든 산출물은 `_workspace/00_source_*.md` (기획 0단계 = 가장 앞단).
- 파일 첫머리에 항상 **단톡방 개요**(멤버 수·기간·화제·톤)를 둔다.
- 통계 나열로 끝내지 말고, 각 항목에 '왜 이게 소설 재료인가' 한 줄을 붙인다.

## 주의
- 통독·받아쓰기·통계 덤프 금지. 샘플링 → 해석 → 가명화 → 구조화.
- 인물 내면 아크는 character-designer, 사건 배치는 plot-architect, 본문은 prose-writer. 너는 '연료'까지만.
- 기획 톤과 소재 결이 다르면 왜곡 말고 story-architect에 보고한다.
